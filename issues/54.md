**Goal:** Develop a robust feature engineering pipeline to convert auction item titles and descriptions into compact word embeddings for downstream ML tasks on price prediction.

### Pipeline Steps

1. **Data Ingestion**
    - Source: [Hugging Face item_data](https://huggingface.co/datasets/jpearce610/item_data)
    - Columns: `item_title`, `item_description`, `auction_id`, `item_id`

2. **Text Pre-processing**
    - Remove English stop words (suggest: NLTK list)
    - Lowercase all text
    - Remove punctuation and special symbols
    - Tokenize using a standard library (nltk, spaCy, etc.)
    - Remove numbers (unless domain-relevant)
    - Combine title and description, but preserve per-item structure
    - Gracefully handle missing or short text fields (skip, warn, or placeholder embedding)
    
3. **Embedding Model Training**
    - Options: word2vec, GLoVe, or FastText
    - Prefer FastText if most titles/descriptions are short and/or noisy
    - Suggested embedding dimension: 100 (or configurable)
    - Train on all available text
    - Parameters:
        - Window size: 5
        - min_count: 2
        - Skip-gram preferred for sparse data
    - Evaluate embedding quality (e.g. by checking nearest neighbors for sample tokens)
    
4. **Embedding Export**
    - For each item: output `{auction_id, item_id, embedding}`
    - File format: Parquet preferred (for scalability), fallback to CSV if needed
    - Save trained model and include instructions on inference for new items
    - Output schema: each row = one item, include auction_id, item_id, and embedding as a vector

5. **Upload & Documentation**
    - Upload output embeddings to Hugging Face hub (`text_embeddings`)
    - Include README with pipeline description and inference instructions

### Success Criteria
- Embedding workflow is reproducible (provide code/scripts)
- Output schema is clear and matches downstream modeling needs
- Reasonable runtime on common laptop (~2GB RAM)
- Handling of all edge cases/improvements documented
