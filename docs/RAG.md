# RAG – Similar Item Retrieval

This document describes the **Retrieval-Augmented Generation (RAG)** feature for
finding past auction items that are similar to a query item.

## Overview

When a user queries the system for a price prediction on an item, it is valuable to
also show them concrete examples of _comparable items that have already sold_.  The
RAG module accomplishes this by:

1. **Embedding** all historical items with FastText (title + description → 100-D vector).
2. **Indexing** those vectors in an in-memory matrix at API start-up.
3. **Retrieving** the top-k nearest neighbours for a new query item using cosine
   similarity (fast matrix-vector dot product on L2-normalised vectors).

```
User submits title + description
              ↓
  Preprocess text  →  FastText embedding
              ↓
  Cosine similarity against index matrix (N × 100)
              ↓
  Top-k similar items  +  historical winning prices
```

## Architecture

### Core Module – `src/rag.py`

| Class / function | Purpose |
|---|---|
| `SimilarItem` | Data class for a single retrieval result |
| `SimilarItemRetriever` | Builds the index and handles queries |
| `SimilarItemRetriever.from_parquet(path)` | Load embeddings from Parquet |
| `SimilarItemRetriever.from_dataframe(df)` | Build from an in-memory DataFrame |
| `SimilarItemRetriever.build_index(df)` | Internal; normalises vectors, stores metadata |
| `SimilarItemRetriever.retrieve(embedding, k)` | Query by embedding vector |
| `SimilarItemRetriever.retrieve_by_text(title, desc, model, k)` | Query by raw text |

### API Endpoint – `POST /similar`

| Field | Description |
|---|---|
| `item_title` | Title of the query item (optional if description provided) |
| `item_description` | Description of the query item (optional if title provided) |
| `k` | Number of results to return (1–20, default 5) |
| `exclude_item_ids` | Item IDs to exclude from results (e.g. the item being priced) |

Response:

```json
{
  "similar_items": [
    {
      "item_id": 123456,
      "auction_id": 7890,
      "similarity": 0.934,
      "item_title": "Vintage Oak Dining Table",
      "item_description": "Solid oak, seats 6, from the 1920s.",
      "winning_price": 145.00
    }
  ],
  "query_title": "Antique Wood Table",
  "query_description": "Old wooden dining table in good condition.",
  "retriever_index_size": 1000000
}
```

## Similarity Method

Embeddings are **L2-normalised** when the index is built.  A query is then answered
by computing the dot product of the (normalised) query vector against all index rows.
This is equivalent to cosine similarity and is fast even for millions of items using
NumPy's BLAS routines.

Cosine similarity ∈ [-1, 1]; in practice auction item embeddings cluster above 0.

## Index Building

The retriever is built at API startup:

```python
from src.rag import SimilarItemRetriever

retriever = SimilarItemRetriever.from_parquet(
    "data/processed/text_embeddings.parquet",
    # optional: merge extra columns (e.g. winning_price)
    metadata_path="data/processed/item_metadata.parquet",
)
```

The embeddings Parquet file is generated by the text embeddings pipeline (see
[TEXT_EMBEDDINGS.md](TEXT_EMBEDDINGS.md)).  If the file does not exist at startup the
`/similar` endpoint returns an empty list without raising an error.

## Python API

### From a Python script

```python
from src.rag import SimilarItemRetriever
from src.text_embeddings import load_model

# Load index (once at startup)
retriever = SimilarItemRetriever.from_parquet("data/processed/text_embeddings.parquet")
model = load_model()

# Query
results = retriever.retrieve_by_text(
    title="Antique Oak Dining Table",
    description="Solid oak, seats 6, from the 1920s.",
    model=model,
    k=5,
)

for r in results:
    print(f"  [{r.similarity:.3f}] item={r.item_id}  price=${r.winning_price}  '{r.item_title}'")
```

### From the REST API

```bash
curl -X POST http://localhost:8000/similar \
  -H "Content-Type: application/json" \
  -d '{
    "item_title": "Antique Oak Dining Table",
    "item_description": "Solid oak, seats 6, from the 1920s.",
    "k": 5
  }'
```

## Data Requirements

The embeddings DataFrame (or Parquet file) **must** contain:

| Column | Type | Required |
|---|---|---|
| `item_id` | int | ✅ |
| `auction_id` | int | ✅ |
| `embedding` | list[float] | ✅ |
| `item_title` | str | optional |
| `item_description` | str | optional |
| `winning_price` | float | optional |

Additional columns are preserved and returned in results automatically.

## Performance

| Metric | Value |
|---|---|
| Index build time | ~2 s for 1 M items (NumPy vstack + normalisation) |
| Memory usage | ~400 MB for 1 M items × 100 dims × float32 |
| Query latency | < 5 ms for 1 M items (single dot product) |
| Embedding dim | 100 (default FastText) |

For datasets significantly larger than 1 M items, consider replacing the NumPy index
with a library like [FAISS](https://github.com/facebookresearch/faiss) for
approximate nearest-neighbour search.

## Future Work

- **Model-served embeddings**: Wire the FastText model loaded at startup into
  `retrieve_by_text` so query embeddings use the same model as the index.
- **FAISS index**: For >10 M items, swap the NumPy index for a FAISS IVF index for
  sub-linear query times.
- **Hybrid retrieval**: Combine text similarity with structured features (category,
  price range, location) for more relevant results.
- **Re-ranking**: After retrieval, re-rank with a cross-encoder or learned metric for
  precision-focused use cases.
- **Gradio UI integration**: Show the top-5 similar items alongside the price
  prediction in the Gradio interface.
